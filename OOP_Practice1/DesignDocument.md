# Дизайн-документ проєкту: OOP_Practice (Command Line Interface)

## 1. Архітектурні шари додатку
Згідно з архітектурним плануванням, проєкт розділений на три основні шари:
1. Шар представлення (Presentation / CLI): Відповідає за взаємодію з користувачем через консольний інтерфейс. Тут знаходяться класи обробки команд та парсингу аргументів.
2. Шар бізнес-логіки (Core): Містить основну логіку програми.
3. Шар постійності (Data / Persistence): Відповідає за зберігання даних.

## 2. Структура консольного інтерфейсу (CLI) та патерни
Для гнучкого керування командами використовується патерн проєктування **Strategy** та компоненти обробки:
1. CLI (Фасад): Головний клас, який керує поточним станом, приймає команди та взаємодіє з бізнес-логікою.
2. ArgParser: Компонент, який відповідає за розбір (`parseArgs`) введеного користувачем рядка на команди та аргументи.
3. ICommandStrategy / SpecificStrategy: Інтерфейс та конкретні реалізації стратегій команд, що дозволяють динамічно додавати нові команди без зміни базового коду CLI.
4. IRenderer / IRenderable: Інтерфейси для форматування та виведення даних на екран.

## 3. Сценарії використання
1. Користувач запускає програму в консолі.
2. `ArgParser` зчитує введений рядок.
3. Активна стратегія (`ICommandStrategy`) виконує відповідну дію.
4. Результат рендериться на екрані через систему виведення.
